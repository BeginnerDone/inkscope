# InkScope 创作平台重构：以完成一章为主线

日期：2026-10-09。本文是研究后的实施规格，不代表下列功能已经实现。

## 1. 研究依据与取舍

本次读了两个仓库的 README、章节工作流、上下文构建、定稿代码；没有安装运行它们，也没有验证其真实模型输出质量。

- AI-Novel-Writer：`b5459befcf1ea667e5157d7931c3a942a1a83238`。
  - `src/shared/draft-status.ts`：草稿、修稿、审稿、定稿、归档区分。
  - `src/services/workflow-guards.ts`：生成前检查上游资料，给出可跳转的补齐动作。
  - `src/services/workflows/commands/review-revision-command.ts`：审稿与确认意见、修订稿、合并来源关联。
  - `src/services/finalization-snapshot.ts`：定稿冻结作者看到的内容；异步完成不能覆盖后续输入。
  - `src/services/workflows/chapter-materials.ts`：材料有来源、必需性、容量和遗漏记录。
- Vela：`5e6a6ec42b7084c02ce4f24b4fec86b40ef2cb33`。
  - `src/services/workflows/chapter-workflow.ts`：章节写作、审稿、修稿、定稿分别执行。
  - `src/services/workflows/commands/generate-draft.command.ts`：围绕章节计划、人物、前文摘要检索上下文。
  - `src/services/workflows/commands/finalize-chapter.command.ts`：定稿后提取摘要、更新知识与连续性材料，步骤可单独重试。
  - `src/services/agent/context-builder.ts`：基础项目信息、编辑器状态、按需读取的材料分层。

采用：明确产物、章节闭环、来源可追溯、材料选择、可恢复任务、作者确认。
保留 InkScope：Tauri、本地数据、真实 shadcn、浅色克制界面、书架/阅读/片段灵感、手动写作。
首版不做：IDE 四分屏/终端、Agent/MCP 管理、自动连写几十章、强制向量服务、市场爆款保证。研究其工作方法，按本项目需要独立实现。

## 2. 当前代码的具体断点

| 当前实现 | 使用中的断点 | 重构方向 |
| --- | --- | --- |
| 页面主要由当前文档 kind 决定 | 用户不知道作品进展、现在应做什么 | 独立的作品总览与章节流程状态 |
| 原文按 Markdown 标题拆成 resource | 文档目录不等于可确认的小说设定 | 导入后整理候选，作者确认，建立引用 |
| 规划是一个 outline 文本，通过标题正则建目录 | 没有可操作的卷/章节计划，已有正文后难继续规划 | 分卷与章节计划独立管理、逐章调整 |
| 章节只有 content、goal | 草稿、修订、定稿没有独立身份 | 每章保存计划、草稿版本、审稿、修订、定稿快照 |
| 审稿候选只供阅读 | 意见无法选择，也无法可靠地交给修稿 | 可编辑、可勾选的意见，确认后生成修订稿 |
| 生成草稿时先整理 memory，采用后写入 facts | 草稿采用和作品定稿混在一起，事实缺少逐条确认 | 定稿后生成记录候选，确认后更新事实和人物状态 |
| resource 按录入顺序取前 16000 字 | 后录入但重要的规则可能不进入本章请求 | 章节显式关联 + 相关检索 + 来源清单 |
| facts 是不断增长的文本 | 多章节人物状态、事实和伏笔难定位或复核 | 每条绑定章节与定稿版本 |

这些问题需要调整模型与任务衔接；导航改名无法完成它们。

## 3. 作者实际使用的流程

### 入口：明确自己处于哪一种起点

1. 只有灵感：填写一句话故事、主要人物和主要冲突，进入故事准备。
2. 有设定/大纲：原文保存为资料；展示待确认人物、规则、规划、问题，再进入故事准备。
3. 有正文：预览章节分割；确认后保留为作者原稿，选择继续位置。可补整理前文记录，无需重新经过全部准备步骤。

来源类型必须由作者确认。原稿、设定、其他作品参考各自隔离。导入的含糊描述不会直接变成已确认事实。

### 主线：准备故事 → 安排当前卷 → 完成当前章 → 进入下一章

| 环节 | 作者操作 | 明确产物 | 完成后进入 |
| --- | --- | --- | --- |
| 准备故事 | 写/整理主角、目标、阻力、核心规则；处理影响开篇的待定问题 | 可编辑故事简案、确认的核心设定 | 安排当前卷 |
| 安排当前卷 | 定阶段目标、冲突推进、卷末变化；先展开近期 3–5 章 | 当前卷计划和章节计划列表 | 当前章准备 |
| 当前章准备 | 明确本章目标、阻力、事件结果、出场人物；选相关资料 | 本章计划、资料清单 | 写草稿 |
| 写草稿 | 手写、AI 起草、续写、局部润色；保存多个版本 | 当前草稿 | 审稿或人工定稿 |
| 审稿 | AI 提建议；作者修改、保留、忽略、补充意见 | 针对特定草稿版本的确认意见 | 修订 |
| 修订 | 仅按确认意见生成；查看变化，逐项/整体采用 | 修订版本；原稿仍可恢复 | 重新检查或定稿 |
| 定稿 | 作者确认当前可见正文 | 不可变定稿快照 | 整理本章记录 |
| 整理记录 | 核对摘要、人物状态、事实、伏笔变化 | 带来源的记录；未确认项保持待核对 | 准备下一章 |

准备阶段允许留白；只有影响当前动作的缺失才提示补齐。所有阶段支持手动完成，AI 审稿不作为定稿的强制前置。

## 4. 页面结构

进入一部作品后，作品内导航只有：**总览 / 故事准备 / 章节 / 资料库**。
全局书架、阅读和灵感仍可返回；作品内避免同时展示两套章节目录。

### 总览

- 作品名、当前卷、写到哪章、最近保存状态。
- 一个主要动作：例如“继续第一章修订”“准备第二章”。
- 最多三个具体提醒：未确认的开篇规则、过期审稿、待核对章节记录。
- 首次项目展示起步任务；已有正文项目直接继续最近章节。
- 不放无用途的完成率、仪表盘图表或一排生成按钮。

### 故事准备

默认展示故事简案与尚待确定的问题；人物、世界规则按需展开。
每项说明“为什么现在需要它”，支持从导入来源选取已有内容。全书方向和当前卷安排分别维护。
不要求先填写几十个人物字段，也不要求提前编完几百章。

### 章节：日常唯一主工作区

左：卷/章节目录，显示每章实际状态，可添加、调整顺序、搜索。
中：当前环节的主要内容；章名下固定流程“准备 → 草稿 → 审稿 → 修订 → 定稿”。
右：仅操作 AI 或查看相关资料时出现的辅助栏；不常驻聊天窗口。

- 准备页：本章计划 + 已选资料，底部只有“开始写作”。
- 草稿页：正文占主位；主操作随状态变为起草、续写、审稿或定稿。
- 审稿页：问题列表，逐条可选；点击问题定位对应段落；作者可自行添加意见。
- 修订页：原文/修改对照，支持保留原文、采用修改；合并后创建新版本。
- 定稿页：正文只读、记录整理状态、准备下一章。修改通过“创建修订版”，不覆盖旧定稿。

按钮只作用于明确的本章、草稿版本和环节。高级写作偏好放到设置，不要求作者选 skill 名称。

### 资料库：支撑写作，按用途查找

默认分类：人物 / 世界规则 / 伏笔 / 正文事实 / 参考与原文。
人物展示稳定设定和截至当前章的状态；伏笔展示埋设依据、推进、预计回收和实际回收。
事实需要正文来源；计划不能直接标为已发生。待确认、已弃用、参考作品默认不作为正式设定注入。
在章节准备中可直接选资料、补条目，再回到原章，无需离开任务查找入口。

## 5. 一章的状态与依赖规则

- 计划确认后可起草；手写可先写，再补计划。
- AI 完成只生成候选；作者采用后才成为当前草稿。
- 审稿绑定草稿版本/内容哈希；正文改变后显示“意见基于旧稿”，禁止静默用于新稿自动修订。
- 修订绑定确认意见的快照与源草稿；保存意见后再改稿，旧修订不得直接覆盖新稿。
- 定稿冻结当前编辑器文字、章节 ID、修订号、内容哈希。
- 本章记录绑定定稿快照；后续修订使关联记录待复核，但不删除旧稿或旧记录。
- 整理记录失败不会损坏定稿；只重试失败步骤，避免重生成正文或重复写入事实。
- 开始下一章时，清楚提示前章记录尚未整理；允许作者选择手动补录后继续，或明确带着缺口继续。
- 不因修改无关作品设置或无关资料就废弃所有候选；依赖所用材料的实际版本。

## 6. AI 的材料怎样选

本章必要资料：本章计划、作者勾选/关联的核心规则与人物、前章结尾。
补充资料：截至当前章的已确认摘要、人物状态、未回收伏笔、相关历史原文。
未来规划单独标明用途，控制泄露；参考文风只提供被选中的素材，不能冒充原作事实。

第一版使用本地关联与关键词/全文检索，能不配置 embedding 就使用。语义向量检索后加，作为补充，不能替代确认与来源管理。
生成前可展开“本次使用的资料”：显示实际来源、版本、被截取/未纳入项。必要资料装不下时，解释需要缩减哪项；不声称通读未提供的内容。

## 7. 最小数据模型与接口边界

保存独立实体：作品、卷、章节计划、草稿版本、审稿报告与意见、修订提案、定稿快照、资料条目、资料来源、章节记录候选、任务步骤。

第一版仍可复用现有本地数据库文件；增加带 schema version 的实体和关联表，不直接拆成一本书一个新数据库。
所有正式写入在 Rust 侧执行事务、版本/来源检查与幂等约束；界面不能仅通过更改标签宣称已定稿。
现有自动保存、草稿恢复、导出、版本能力保留。

对生成定义不同输出契约：正文与修订正文使用文本；章节计划、审稿意见、记录候选使用简单结构化数据。
结构化输出出错保留原返回和任务进度，修复当前结果或允许手动整理；不反复重生成已完成正文。
技能作为环节背后的写作方法：简案整理、当前卷规划、本章准备、起草、审稿、按意见修订、记录整理。

## 8. 老项目如何迁移

- source 原文只读保留，resource 作为已有资料导入，不自动改写作者文本。
- brief 进入故事简案；outline 作为规划来源，转换成章节计划需预览确认。
- chapter 保留 ID、顺序、标题、正文，默认视为作者草稿；是否作为原稿定稿，由作者选择。
- facts 旧文本保留为历史记录；逐条整理后再建立章节来源，不伪造旧内容已确认的状态。
- 保留版本与 AI 候选历史；旧无依赖标识的候选只供阅读/复制，不自动并入新流程。
- 迁移可重入、可校验，写入失败事务回滚；不以替换用户数据库来测试迁移。

## 9. 实施顺序与验收

### 第一阶段：完成可用的单章闭环

先落实实体与迁移、作品总览、章节工作区、本章计划、草稿/审稿/修订/定稿及记录待确认；接通现有模型与本地保存。
完成条件：从一个最小故事准备，规划 3 章，完成第一章并准备第二章，整个过程无需在“更多”中找主功能。
必须包含人工直写、AI 失败恢复、审稿过期、修改合并冲突、定稿后修订；不是只有正常路径的界面原型。

### 第二阶段：让资料确实帮助长篇续写

完善设定导入候选整理、逐章人物状态、伏笔与事实来源、本地检索和材料预览。
完成条件：第二章调用实际相关资料，能解释每条事实来自哪份定稿，不能把第一章未采用的草稿当成已发生事件。

### 第三阶段：提高长期效率

按需加入有限章数批量任务、费用/调用记录、语义检索、跨章调整影响检查。
前两阶段未走通前，不增加 Agent 控制台、插件市场或更多工作台标签。

### 用户提供的设定文件验收路径

导入“设定总览_当前版.md” → 预览原文与用途 → 整理并确认故事简案/人物/规则 → 尚未确定的出生世界、力量机制等留为问题 → 选择需要开篇处理的问题 → 规划当前卷与前三章 → 准备第一章 → 写稿 → 勾选审稿意见 → 预览修订 → 定稿 → 核对本章记录 → 第二章。

不能把设定中的标题直接当小说章节，不能自动将终局备选变成已发生事实，不能要求作者把所有设定先抄进几十个字段。

验收分开记录：纯数据/状态测试、浏览器交互与窄窗口检查、原生安装启动检查、真实模型生成质量。前面三类通过不代表真实生成效果已验证。
